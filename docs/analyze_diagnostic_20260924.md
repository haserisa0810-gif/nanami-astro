# 2026-09-24 通常鑑定の動作調査

## 結論

ユーザー提供のエラー画像は、JSONの `detail` に入った「出生地は都道府県を選ぶか、地図で地点を選択してください。」が文字化けした表示と一致する。出生地の都道府県または緯度・経度がサーバーに渡っていないと、通常鑑定はHTTP 400で終了する。今回確認した失敗はタイムアウトではない。

画像の文字化けは、上記日本語のUTF-8バイト列をCP932として復号した文字列で照合した。どのブラウザー処理で文字コードが誤認されたかは未確定。

## 対応案

直近の回避方法は、都道府県を明示的に選択して再実行すること。地図を使うなら、検索だけでなく地点を選び、緯度・経度が設定された状態で実行する。

フォームの `都道府県（任意）` と `緯度・経度（任意）` は、両方不要と受け取られやすい。出生地は「都道府県または地図・座標のいずれか必須」と明示し、送信前に検証する改善が適切。サーバー側の入力エラーもJSONだけを直接表示せず、日本語のHTML案内と入力に戻る導線を設けると原因が伝わる。

上記の初回調査ではアプリケーションのコード・本番設定は変更していない。

## エラー表示の修正・本番反映

その後の「エラーが読めない問題を解決したい」という依頼に対応した。

- `POST /analyze` のHTTPエラー、入力検証エラー、予期しない例外を専用の日本語HTML画面で表示する。HTTPヘッダーに `text/html; charset=utf-8`、HTML先頭に `meta charset="utf-8"` を設定。エラーのHTTPステータスは維持する。
- 戻るリンクを追加。同一サイトから来た場合はブラウザーの履歴を使って入力内容を復元し、履歴がない場合やJavaScriptが無効でも通常のリンクとして使用できる。
- 必須項目・数値形式の検証メッセージを日本語化。内部例外や検証対象の入力値をエラー画面に載せない。表示する文章はHTMLエスケープする。
- 出生地の案内を「都道府県または地図・座標での指定が必須」と明示する。
- 推奨設定APIなど、通常鑑定フォーム以外のJSON応答は変更しない。
