# 2026-09-23 note生成エラーの修正

## 原因

Cloud Run `nanami-astro-00913-jg2` のビルド `ebcb9e86-ff25-4a47-a99c-4a782a25194a` では、版指定のない `anthropic` 依存により SDK 1.8.0 が入った。

このSDKは `Messages.create(..., temperature=...)` を受け付けず、API送信前に `TypeError: Messages.create() got an unexpected keyword argument 'temperature'` が発生する。同版を隔離環境に入れ、偽APIキーとHTTPモックで再現した。Haikuの5000/14000トークン設定の両方で同じ例外になる。

画面側は例外を捕捉していたがログに残さず、入力やAPI設定を確認する汎用エラーだけを表示していた。そのためアクセスログではHTTP 200となり、失敗理由が追えなかった。

## 修正

- `anthropic==0.125.0` に固定。既存の呼び出しと互換性があり、Haiku/Sonnet、通常記事/12星座の4通りで実SDKを通したオフライン回帰テストを追加した。HTTPだけを模擬し、実API呼び出しや課金は行わない。
- 想定外の例外をサーバーログへスタックトレース付きで記録する。画面には内部例外を表示せず、再試行と調査に必要な情報の案内を出す。
- 今後SDKを上げる場合は、このテストを通してから依存の固定版を変更する。`**kwargs` を受ける偽物のクライアントだけではSDK側の破壊的変更を検知できない。

## デプロイ元

上記リビジョンのイメージダイジェストとCloud Buildの出力ダイジェストは一致する。取得したソースには、前回Codexが追加した `planetary_motion.py` と `note_writing_contract.py` がなく、前回の星座別プロンプト・逆行修正はまだ本番に入っていなかった。

復旧用のソースは、その稼働ソースを基に、このSDK修正と前回依頼の9ファイルを重ねる。ローカルで別途変更されている受注・メール関連のファイルは混ぜない。一時アーカイブやビルド用コピーはOneDrive外の `C:\Users\haser\work\staging` に置く。
