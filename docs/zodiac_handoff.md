# 月次12星座の生成とAIへの引き継ぎ

YAMLをClaude・Codexへ渡すときは、次の依頼を添える。

> このYAMLの writing_instruction に従って、12星座別の読みを深めて書いてください。既存下書きの分割や整形だけで終えず、星座ごとの主役・生活場面・迷い・具体的な行動を計算済みデータから組み立ててください。参考記事は構成と語り口の参考にし、天体の事実は今回のYAMLを使ってください。

`zodiac_handoff_request` にも同じ目的の依頼が入っている。記事を個別ファイルにするか、note貼り付け本文にするかなどの出力指定は、依頼時に添える。参考原稿や出力先は毎回指定し、過去月のリンク・公開状態・天体配置を持ち越さない。

## 書き分けの基準

- 星座別本文は500〜750字を目安とし、共通の全体運や案内文を除いて読みの分量を確保する。
- 主役の配置を1〜2個選び、両ハウスの関係と在泊天体・支配星から、その星座の場面と葛藤を読む。
- 同じアスペクトを使っても、星座名だけ交換できる文章にしない。具体的な行動までつなげる。
- 最後に `quality_check` で、根拠との一致、星座ごとの差、具体性を見直す。

実装は `services/note_writing_contract.py` に集約。アプリの「12星座別運勢」と出力YAMLの両方から使う。アプリの生成先は既存のClaudeのまま。Codex利用はYAMLの受け渡しで行う。

2026年9月23日に照合した10月の個別12記事は、統合原稿の星座別本文と全12件同一だった。分割の確認だけでは、新規に生成した文章の質の評価にはならない。変更後の本文を並べて、主役・葛藤・行動の差を確認すること。プロンプトのテスト成功だけでClaudeとCodexの文芸品質が同等と判断しない。

## 逆行と留の根拠

- `daily_snapshots.planet_positions[].retrograde` は、既存のSwiss Ephemeris計算の丸め前の速度による判定を保持する。位置の小数2桁から向きを推測しない。
- `station_events` は水星・金星・火星の速度の符号が変わる時刻を二分探索する。日本時間で月初を含み翌月初を含まない期間を対象にし、前月末も調べる。探索の時間幅は1秒以下。
- `zodiac_context` 自体は天体を再計算せず、上の計算済み値を受け取る。
- 古いデータで方向が不明なら `retrograde: null` を維持し、留の日付も創作しない。`motion_data.stations` で未取得と計算済みを区別する。
- 月初・月末配置は日本時間12時の状態。留の当日でも、正午前後で逆行状態が異なることがある。
- 入座日は従来の日次サイン変化の確認日。アスペクトの日付も従来の日次観測の最小orbの日であり、精密な成立時刻ではない。アスペクトの開始・終了には離れた期間が統合される既知の制約があるため、連続期間として読み上げない。

回帰テストは `tests/test_zodiac_context.py` と `tests/test_note_zodiac_regressions.py`。6月末の水星、4月初めの火星、外惑星、年跨ぎ、閏年、正確な月境界、古いデータ、実際にAPIへ渡すプロンプトを検証する。APIクライアントは偽物を使い、外部送信や生成料金を発生させない。

執筆基準の構成は、[OpenAIのプロンプト設計ガイド](https://developers.openai.com/api/docs/guides/prompt-engineering)の、目的・具体的な文脈・例・評価を揃える考え方も参考にしている。
